# Use a single Python prediction entry point

This decision applies only to generated Python; SQL retains its typed-column and engine-specific missing-value behavior. Generated Python exposes `predict` as its only prediction function and intentionally does not retain the former `predict_row` name. `predict` delegates all required-key checks, value validation, default filling, and feature-aware normalization to a separate preparation function before evaluating any tree. The preparation function contains clear Chinese comments explaining each step. It recognizes object, numeric, and textual raw missing markers; without a fill rule these become `NaN`, zero-missing rules may also turn zero into `NaN`, and model rules that compare source missing values as zero normalize them to zero before tree evaluation. The generated file defines an editable missing-text set near its top, initially containing `""`, `"nan"`, `"null"`, and `"none"`; a stripped, lowercased copy of an input string is used only for this membership check, while a non-missing categorical string retains its original spelling and whitespace. Every non-missing numeric feature value is converted to `float`, including numeric strings such as `"12.3"`. Preparation first raises one `KeyError` listing every absent required scoring feature; only when all keys exist does it attempt conversions, raising one `ValueError` listing every invalid numeric feature and original value. Both error stages finish before any tree is evaluated. Tree functions use direct indexing and may detect only the normalized `NaN` state; they contain no `.get()`, raw missing-marker handling, input conversion, or input-error handling.
